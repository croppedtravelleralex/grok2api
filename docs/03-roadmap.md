# grokImage 路线图

本文件只记录阶段目标和里程碑，不记录无界执行细节。

## Now

### 1. 图片管理与账号池稳定化上线

- 目标：上线日期管理、详细图片元数据、Web 单并发保护和 Build 异常账号恢复路径。
- 预期产出：可用管理页面、批量删除 API、受限 Web 出口、可解释的 Build 异常状态。
- 进入条件：本地后端测试与前端构建全部通过。
- 完成标准：Panda 健康部署，图片页面验收通过，单 Web 请求 canary 有明确结果；失败时不扩大全量任务。
- 依赖关系：GitHub Actions/GHCR、Panda 可用内存至少 1 GiB且负载满足门槛。

## Next

### 0. 账号探活可视化（P0，2026-07-16，已完成）

- 目标：在 `accounts` 页看见固定单并发循环探活的当前账号、成功失败、阶段、调度时间和分池结果。
- 已交付：只读 `GET /api/admin/v1/accounts/build-probe` + 5 秒轮询的前端状态面板。
- 完成标准：网页可看到探活走到哪、当前进程累计计数、七类池数量与最近结果；无需 SSH 读 journal。
- 安全边界：Panda 保持固定单并发后台 worker，不在管理页暴露 1–5 并发或人工批量启动，避免误操作打满低资源生产机。

### 1. 凭据恢复和浏览器会话稳定化

- 目标：把“代理可用、Cloudflare 403、SSO 失效、无 Build 权限”分成可操作状态。
- 预期产出：单账号诊断证据、浏览器桥接健康检查、新 RT 重导入流程、2 个关联 Build 账号的恢复结果。
- 进入条件：本轮生产部署稳定；当前已完成 2 个关联 Build 账号恢复。
- 完成标准：不会对不可恢复账号重复刷新；可恢复账号可通过新凭据回到 active；Web 失败能在 30 秒内给出明确阶段。
- 依赖关系：有效 SSO/RT、上游账号权限，以及可建立 Grok Cloudflare 会话的住宅/ISP 出口。

### 2. Build 可信账号池扩展

- 目标：把“Token 可刷新”和“真实 Build Chat 可调用”分开验证。
- 预期产出：单并发最小能力探测、最近成功型号记录、生产/验证/隔离/恢复/退役五类调度池。
- 完成标准：生产请求只进入已验证账号；探测任务不超过并发 1，失败不会被普通 Token 刷新重新激活。
- 依赖关系：有效新 RT 或具备 Build Chat 权限的新授权。

### 3. Web 浏览器身份连续性 canary

- 目标：验证同代理、同 SSO/clearance、同 UA/平台和同浏览器会话复用后能否建立 Grok Cloudflare 会话。
- 完成标准：只用一个浏览器和一个账号得到明确 2xx 或阶段化失败；失败时桥接被停止且主服务资源无明显波动。
- 依赖关系：当前 Webshare 节点信誉；若仍被拒绝则需要粘滞住宅/ISP 出口。

### 4. Grok Web HTTP 逆向（类 gptimage，P0）

- 目标：用 HTTP（`curl_cffi`/等价 TLS 伪装）完成 chat/imagine，浏览器仅清障。
- 预期产出：抓包清单、最小 PoC（登录态请求生图或 chat）、与现有 browser-bridge 的切换开关。
- 完成标准：至少一条 Web 路径不经每请求 Chromium 成功返回；Panda 资源占用显著低于 bridge。
- 依赖关系：能过 CF 的出口（住宅/ISP 或 clearance）；对照 `/root/gptimage` 实现模式，接口需 grok 专用。
- 2026-07-22 状态：本地已实现每请求新签名票、纯 HTTP Lite 流水线、显式 FIFO/aging 和实时槽位/队列；当前生产旧镜像 80/80 上游 403，仍须新镜像 1→2→4→10 canary 后才能标记完成。

## Later

### 1. 受控扩容与长期可观测性

- 目标：在真实资源数据支持下评估 Web 并发从 1 提升到 2，并完善账号错误趋势、刷新成功率和代理节点指标。
- 预期产出：按错误码、Provider、时间维度的趋势图和带停止阈值的容量报告。
- 完成标准：提升并发不会触发 Panda 资源门槛、Cloudflare 风控或 Webshare 限制。
- 依赖关系：稳定的单并发基线和足够长的生产观测窗口。

# grokImage 路线图

本文件只记录阶段目标和里程碑，不记录无界执行细节。

## Now

### 1. 图片管理与账号池稳定化上线

- 目标：上线日期管理、详细图片元数据、Web 单并发保护和 Build 异常账号恢复路径。
- 预期产出：可用管理页面、批量删除 API、受限 Web 出口、可解释的 Build 异常状态。
- 进入条件：本地后端测试与前端构建全部通过。
- 完成标准：Panda 健康部署，图片页面验收通过，单 Web 请求 canary 有明确结果；失败时不扩大全量任务。
- 依赖关系：GitHub Actions/GHCR、Panda 可用内存至少 1 GiB且负载满足门槛。

## Next

### 1. 凭据恢复和浏览器会话稳定化

- 目标：把“代理可用、Cloudflare 403、SSO 失效、无 Build 权限”分成可操作状态。
- 预期产出：单账号诊断证据、浏览器桥接健康检查、新 RT 重导入流程、2 个关联 Build 账号的恢复结果。
- 进入条件：本轮生产部署稳定；当前已完成 2 个关联 Build 账号恢复。
- 完成标准：不会对不可恢复账号重复刷新；可恢复账号可通过新凭据回到 active；Web 失败能在 30 秒内给出明确阶段。
- 依赖关系：有效 SSO/RT、上游账号权限，以及可建立 Grok Cloudflare 会话的住宅/ISP 出口。

## Later

### 1. 受控扩容与长期可观测性

- 目标：在真实资源数据支持下评估 Web 并发从 1 提升到 2，并完善账号错误趋势、刷新成功率和代理节点指标。
- 预期产出：按错误码、Provider、时间维度的趋势图和带停止阈值的容量报告。
- 完成标准：提升并发不会触发 Panda 资源门槛、Cloudflare 风控或 Webshare 限制。
- 依赖关系：稳定的单并发基线和足够长的生产观测窗口。

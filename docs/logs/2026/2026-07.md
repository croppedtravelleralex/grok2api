### Messages、Build 可信池与 Webshare 深度诊断

- 复现 NewAPI Messages 间歇性 403：请求正确进入 Build Messages 渠道，但所选 active 账号被上游返回 `permission-denied`；Claude Code 将下游 403 误解释为需要 `/login`。
- 修复 Build 权限拒绝后的错误恢复：不再强制刷新 RT；Token 更新不会把 `chat endpoint access denied` 账号重新置为 active。
- 生产选号增加可信池保护：存在成功观测型号时，仅使用已验证 Build 账号，未验证账号不再由用户流量试错。
- 修复 Chat/Messages 对外模型名：公开返回 `grok-4.5`，内部继续保留真实观测型号。
- 修复 Anthropic Messages 流式 usage：合并 `message_start`/`message_delta`，记录输入、输出、缓存命中，并为 `cache_control` 稳定前缀派生粘滞键。
- 永久 Build 权限拒绝对外改为 503；Anthropic 使用 `overloaded_error`，避免客户端提示重新登录。
- Webshare 诊断确认：100 个 IP 仅覆盖 10 个 `/24`，均为新加坡机房 ASN；Panda 代理鉴权可用但 Grok Cloudflare 会话被拒绝，问题不是白名单或单纯并发。
- 本机验证：受影响包测试、`go test ./...` 与 `go build ./cmd/grok2api` 均通过。
- 追加 Build 可信池扩展：重新导入异常账号会清除旧观测型号；后台按 5 分钟 1 个的节奏发起最小 Responses 能力探测，避免生产流量试错。
